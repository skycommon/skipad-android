# 跳过广告 · Android 版 v3.4

一个开屏广告自动跳过工具。只在**你打开某个应用的最初几秒**读取当前界面，
寻找写着「跳过 / 跳过广告 / Skip」之类的按钮并自动点掉，之后立即停止。

**不联网、不上传、不读取输入框、不修改任何系统设置。**

## v3.4：开机即生效 · 卡住自救（解决「开机后不跳」和「卡在超级课程表进不去」）

用户反馈两件事：

> **"有时候会出现开启手机以后无法启动这个跳过广告的操作。还有如果这个手机开启以后处在一个应用界面里面，有可能无法退出。均卡在超级课程表的这个启动界面无法进入。"**

翻译成两个具体故障：

| 故障 | 表现 |
|---|---|
| **A. 开机后不工作** | 手机重启后，无障碍开关看着还是开的，但跳广告完全没反应；手动进设置关一次再打开就恢复了 |
| **B. 卡死在某应用开屏页** | 开屏广告盖满全屏，「跳过」点了不生效，返回键也退不出，卡在超级课程表启动页 |

### 故障 A 的两个根因

**根因 1：整套逻辑是纯事件驱动的，一条事件都没来就永远不动。**
v3.3 的所有动作都由 `onAccessibilityEvent` 触发。开机时系统在很早的阶段就拉起无障碍服务，
那一刻 ROM 可能把首批事件全部吞掉（或事件到达时窗口还没建好），而此后再没有任何机制主动看一眼
—— 于是服务"活着但一动不动"，直到用户手动关开一次开关才重新开始收事件。

**修法：加一个与事件完全无关的看门狗（`fgPollMs`，默认 700 毫秒）。**
新增 `pollForeground()`：按固定周期自己去读当前前台是哪个应用（`getRootInActiveWindow()`），
喂给和事件路径**完全相同**的决策函数。这样即使一条无障碍事件都没收到，也能发现"用户打开了某个应用"
并开始观察。观察期内轮询自动提速到间隔的一半（最快 220 毫秒），开屏广告只存在几秒，早一眼看到就能早点跳掉。

> 读不到前台时还有一层兜底：广告 SDK 的覆盖窗口可能成为"活动窗口"，此时活动包名是广告 SDK，
> 不是我们关心的应用。这时 `findWatchableWindowPkg()` 会遍历全部窗口，找出真正需要监听的那个应用包名。

**根因 2：服务连接后没有重新登记无障碍能力。**
部分 ROM 在开机拉起服务时会给一个「事件类型 / flags 都为空的 `AccessibilityServiceInfo`」——服务在跑，
却收不到任何事件。所以 `onServiceConnected()` 现在会 `refreshServiceInfo()`：把当前 info 原样写回，
等于让系统按 xml 配置重新登记一次监听；并在 1500 毫秒后再补一次（防止系统在连接瞬间覆盖）。

**另加一条「服务自检」日志。** 这是给排查用的：打开「查看日志」，如果**开头没有**这一行
「服务自检 · vN.N 已连接 · 总开关开 · 扫描线程就绪 · 前台轮询已启动」，说明**系统压根没拉起服务**，
该去查电池优化 / 自启动；有这一行却仍不跳，才是规则或界面问题。一眼分清，不用猜。

### 故障 B 的四个根因

**根因 1：观察窗口只有 6 秒，而广告常常 8~12 秒才盖上来。**
「启动页 → SDK 拉素材 → 广告盖上来」这个链条在弱网下经常要 8 秒以上。6 秒窗口在广告出现前就关了，
之后广告再盖满屏幕也没人管 —— 用户看到的就是"卡在启动页"。

**修法：`splashWindowMs` 默认 6000 → 12000。** 观察窗口翻倍。

**根因 2：v3.3 的「首屏切走收手」把「启动页 → 广告页」判反了。**
v3.3 的早停逻辑是：进入观察 1.5 秒后，若当前界面文字与首屏指纹差异 ≥ 50% 且没命中候选，就收工。
但「启动页换成广告页」恰好就是大幅换屏 —— 于是**广告刚盖上来，服务就主动收手了**，
这正好是最该干活的那一瞬。

**修法：`firstScreenExit` 默认改为 `false`（关掉）。** 早停逻辑保留但默认不生效，
只在用户明确想省电、且确认自己常用的应用没有延迟广告时才打开。

**根因 3：`FG_LEAVE` 分支少了 `return`（这是一个真 BUG）。**
v3.3 里"用户已离开应用"的处理是：`endWatch(false)` 之后**继续往下执行**，于是又在**桌面**上
重开了一轮 6 秒观察。后果有三层：

- 「离开即停」这个 v3.3 的主打功能**实际上从未生效过**；
- 桌面包名在 `excludeApps` 里，窗口被全部跳过 → roots 为空 → 兜底用 `getRootInActiveWindow()` 扫桌面；
- 桌面上若有像「跳过」的文字就会被点，而且每回到桌面就重置一次，反复触发。

**修法：`FG_LEAVE` 分支 `endWatch()` 后立刻 `return`**，并写一条 `Log.i("用户已离开，结束观察且不再重开")`。

**根因 4：跳过按钮是纯图片 / 视频覆盖层时，控件树里根本没有这个节点。**
有些广告 SDK 把「跳过」画在 Surface / 视频层上，无障碍读不到任何节点 —— 找候选必然为空，
只能干等到超时。用户按返回键往往就能结束这种广告，但服务不会替用户按。

**修法：新增「卡住自救」（`backKeyFallback`，默认 `true`）。**
条件非常严：必须**确认当前是广告页**（`detectAdPage()` 在控件树里找到 `adTexts` 特征，如「摇一摇」「互动广告」），
且广告页已持续 `backKeyDelayMs`（默认 3500 毫秒）仍跳不掉，且本轮还没跳过、没按过返回键 ——
才 `performGlobalAction(GLOBAL_ACTION_BACK)` 按一次返回键。普通界面**绝不触发**。

> 为什么按返回键是安全的：广告 SDK 普遍把开屏页的返回键重写成「结束广告」，对用户等价于跳过。
> 而且这也正是"退不出"的唯一出路 —— 用户自己按返回键做的事，和这里做的是同一件事。

**另有两处「不再一刀切」的放宽：**

- **不安全候选不再一次就收工**：v3.3 只要出现一个落在安全带外的候选就 `endWatch`，很容易被
  广告页里的正常按钮骗走。现在改为容忍 `unsafeRejectLimit`（默认 3）次才收工。
- **冷却只对「上一轮真的跳成了」生效**：v3.3 的冷却（同应用两次观察之间等 `episodeCooldownMs`）
  不区分上一轮有没有成功。结果是"开机那一下没跳成，之后怎么开这个应用都不跳，要等 1 分钟"。
  现在 `FgContext.lastEpisodeHit` 记录上一轮是否真跳成功过，没成功就不冷却。
  同时冷却时长从 60000 收紧到 **8000**（8 秒）—— 冷却的目的是防止把扫描带进正常界面，
  8 秒足够，60 秒纯属让用户干等。

### 顺带修掉的性能问题

v3.3 的扫描、轮询、以及"点击前复核位置"（`stillSameNode` 会遍历所有窗口做整树深搜，深度 40）**全在主线程**。
100 毫秒扫描 + 250 毫秒轮询 + 两次全树遍历叠在一起，观察期内界面会明显发涩。v3.4 把整套状态机搬到
名为 `skipad-worker` 的 `HandlerThread` 上，主线程只留 Toast 和震动。

### 新增的配置项（都有默认值，不改也能用）

| 字段 | 默认 | 作用 |
|---|---|---|
| `fgPollMs` | `700` | 前台轮询间隔（毫秒），范围 150–3000。与无障碍事件无关的看门狗，**这是"开机即生效"的关键**。观察期自动减半，最快 220 |
| `firstScreenExit` | `false` | v3.3 的"首屏切走收手"。**默认关**，因为它会把"启动页→广告页"判反 |
| `unsafeRejectLimit` | `3` | 出现不安全候选几次后才收工（原为 1 次就收） |
| `backKeyFallback` | `true` | **卡住自救**：确认是广告页且久久跳不掉时，自动按一次返回键 |
| `backKeyDelayMs` | `3500` | 确认广告页后等多久才按返回键，范围 800–20000 |
| `splashWindowMs` | `12000` | **由 6000 改为 12000**，观察窗口翻倍 |
| `episodeCooldownMs` | `8000` | **由 60000 改为 8000**，且只对"上一轮真跳成了"生效 |

界面上也加了对应开关：**卡住自救（按返回键）**，默认开。
规则摘要区会显示当前观察窗口、前台轮询间隔、冷却时长和自救状态。

### 超级课程表（京东开屏广告）专项

`apps` 里新增 `com.tencent.pocket`（超级课程表），带 `extraTexts` 与 `extraIds`
（`*:*skip*`、`*:*splash*`、`*:*ad*close*`、`*:*close*ad*`、`*:*countdown*`）。
`skipIds` 也补了 `*:*countdown*`、`*:*ad_time*` —— 京东那种「跳过 | 2」的倒计时角标，
id 名里通常带 countdown / ad_time。`adTexts` 补了 `互动广告`、`开屏广告`、`跳过并关闭`
（**刻意不收裸词「广告」**：正常页面太常见，收了会把全屏放宽）。

## v3.3：退出即停 · 首屏切走收手（解决「退出后反复点回去」）

用户反馈（v3.2 之后仍存在的体验问题）：

> **"着急想退回界面，这个应用没有广告的话，退出以后会反复点回去。"**

典型场景：打开一个**没有开屏广告**的应用（或开屏已经正常结束），用户马上按返回 / 切到桌面 / 进设置改东西。此时 v3.2 的观察窗口还开着，会把这个「正常界面」当成广告界面继续扫、反复找「跳过」去点，于是出现「明明没广告，却像被反复点回去」的错觉 —— 本质不是点错，而是**观察收得太慢、点得太勤**。

**根因**：两处「观察窗口结束」机制不够及时。

1. **前台切换决策没把「退出」当回事**。v3.2 的 `decideForeground` 在「观察中 + 桌面」时只把状态置为 `FG_KEEP`（继续观察）。用户回到桌面后，服务仍在扫桌面（桌面已被 `excludeApps` 挡下、不会误点，但会一直空扫、不收工），更糟的是用户从桌面再进别的应用，这一轮观察仍挂在前一个应用上，容易让人觉得「点回去了」。
2. **首屏一旦切走没有早停**。观察期内只要没命中跳过，就一直扫到 `splashWindowMs`（6 秒）/ `episodeCooldownMs`（60 秒）自然结束。而「没有广告、已经正常进入应用」的情况，前 1~2 秒界面就该和开屏大不一样了，继续扫纯属多余。

**修法：退出即停 + 首屏切走收手。**

- **新增 `FG_LEAVE` 决策**：观察中若前台切到「桌面 / 设置 / 安装器 / 系统 UI / 本应用自身」等 `excludeApps` 包名，直接 `endWatch()` **立刻收工**（不再像 v3.2 那样 `FG_KEEP`）。只剩「广告 SDK 独立窗口 / 另一个正常应用窗口」仍 `FG_KEEP`（继续观察，不换锚点）。这样：用户一回到桌面，本轮观察当场结束，不再空扫、不再挂着。
- **首屏文字指纹早停**：进入观察后 3 秒内抓一次「首屏文字指纹」；之后若**始终没命中任何候选**，且当前界面文字与首屏指纹**差异 ≥ 50%**（说明用户已经正常进入 / 离开应用，而不是卡在开屏广告上），则标记 `leftFirstScreen` 并 `endWatch()` 收工。阈值 0.5、起始延迟 1500ms、指纹采集窗 3000ms，避免开屏倒计时数字变化造成的误判。

> 说明：v3.2 其实有 `excludeApps` 兜底（桌面/设置等窗口不被扫描、不会误点），所以 v3.3 修的是「收工太慢、还在空扫」的体感问题，而非「真的点错了」。但既然会让人误以为被反复点，就必须收得快。

`shakeAware` / `shakeBlindTap` / `identified`（身份已确认）行为均不变。

## v3.2：大「跳过」条、广告 SDK 关闭键、互动广告，都能关了

用户又反馈（v3.1 之后仍跳不掉的三类）：

1. **有「跳过」字样却跳不掉** —— 某些开屏广告的「跳过」做成一整条「文字 + 倒计时」的宽条，面积超过 v3.0/v3.1 的面积上限（0.12 / 0.25），被当成「太大不要」直接拦下。
2. **「互动广告」关不了** —— 互动广告的「关闭 / ×」键常是纯图标且落在屏幕中部，既过不了「必须有文字依据」闸门，也落在安全带之外。
3. **广告 SDK 的关闭按钮、开屏关闭键** —— 同 (2)，纯图标、位置不固定。

**根因**：v3.0/v3.1 为「宁可不跳、绝不误触」给候选加了三道形状约束（面积必须小 + 必须靠屏幕边 + 必须有文字）。对「小且靠边的跳过按钮」很准，但对下面这些确实是跳过/关闭的控件会一刀切错杀 —— 而这些控件一旦确认是「跳过/关闭」，点错风险极低：

- 带倒计时的大「跳过」条：面积大，但文字就是「跳过」，铁证；
- 广告 SDK 的 `*:*close*` / 开屏 `*:*splash_close*` 关闭键：ID 即铁证；
- 互动广告的「关闭」：文字即铁证，哪怕位置靠中间。

**修法：身份已确认，就解开形状约束。** 候选**精确命中 `skipTexts`** 或 **命中 `skipIds`** 时即视为身份已确认：面积上限从 `safeMaxArea`/`adMaxArea` 放宽到容器级 0.55（只挡真正全屏容器，防点进广告落地页）；位置安全带彻底解开（但仍不点全屏容器）；「必须有文字依据」闸门也一并免除（纯 ID 命中的图标关闭键即可点）。普通按钮（靠关键词/强词命中、没命中 ID）仍走旧的严格形状约束。

> **唯一仍死守的硬约束**：面积 > 0.55 的节点一律不点 —— 那是广告大图/视频容器，点中会跳转，无论文字多像「跳过」都不能点。

同时扩充了默认规则救更多「关不掉」的控件：`skipTexts` 新增 `关闭该广告`/`点击关闭`/`关闭广告X` 等；`skipIds` 新增 `*:*splash_close*`（开屏关闭键）等。

## v3.1：摇一摇广告也能跳了（并且不牺牲防误触）

用户反馈：**页面上出现「摇一摇」或「摇动手机」字样时，就不会自动跳过了。**

这不是随机失灵，而是 v3.0 自己造的回归 —— 它的两道闸门同时挡下了这类广告：

| 挡在哪 | 为什么摇一摇广告会撞上 |
|---|---|
| **安全带太窄** | 摇一摇广告把品牌 logo 和「摇一摇」提示放在屏幕**最上方**，于是把「跳过」挤到纵位置 **0.30~0.55** 一带 —— 正好落在 v3.0 只允许的「顶部 30%」之外，被判为不安全 |
| **必须有文字依据** | 这类广告的「跳过」常是**纯图片**（一个圆圈加斜杠，没有文字），过不了「必须文字命中」这道闸门 |

### 修法：不拆防线，改成"看证据放宽"

最直接的做法是把安全带整体放宽，但那等于**全屏可点**，v3.0 好不容易挡住的
误触（抖音搜索图标）会原样回来。所以 v3.1 改成一个**有条件**的放宽：

> **只有当页面上确实出现了摇一摇类特征文案时**，才判定"这确实是广告页"，
> 进而启用一套**更宽但仍有边界**的安全带，并允许点击无文字的跳过按钮。

判定依据是 `adTexts`（新增，14 条）——刻意**只收「摇一摇 / 摇动手机 / 晃动手机 /
翻转手机 / 跳转第三方」这类广告专属措辞**，不收「立即下载」「点击下载」等正常页面
也会出现的词。收窄的代价是漏放宽，但宁可漏放宽，也不能因为一个正常页面写着
「立即下载」就把全屏变成可点区域。

### 放宽后仍然守住的边界

放宽**不是**取消。广告页的安全带是另一组参数，且**仍然留有不可点击的中间走廊**：

```
普通页（v3.0 不变）      顶部 0 ~ 30%   ✅     中间 30%~75%  ❌     底部 75% ~ 100% ✅
摇一摇广告页（v3.1）     顶部 0 ~ 60%   ✅     中间 60%~75%  ❌     底部 75% ~ 100% ✅
                                       ↑ 走廊仍在，面积上限 0.25（普通页 0.12）
```

**真正的放宽发生在上方**：痛点就是「跳过」被顶部 logo 挤到 0.30~0.55 那一带，
所以把顶部带从 30% 扩到 60%。底部带**没有动**（`adBottomBand` 默认为 0.75，
和普通页一致）—— 它的语义是「底部带从哪开始」，被钳制在
`[0.30, safeBottomBand]` 内，只能**往上挪**以扩大可点范围，不能往下挪，所以
默认值保持与普通页相同即可，不需要额外放宽。

即便如此，那条**贯穿屏幕中部的走廊依然一律不点** —— 那里是正文、输入框和内容区，
是误触代价最高的地方。参数也各自钳制（`adTopBand ≤ 0.80`、`adMaxArea ≤ 0.55`，
且保证上下带之间至少留 0.05 的走廊），即使规则文件被改坏也不会退化成全屏可点。

**`shakeAware` 默认开**（摇一摇放宽总开关）；**`shakeBlindTap` 默认关**
（"无文字依据也直接点"的激进模式，不开）。把 `shakeAware` 关掉，
行为就完全回到 v3.0。

### 一次扫描变成两趟

实现上是**两趟扫描**：第一趟照常找候选，同时顺手记录页面上有没有广告特征文案；
第二趟把「是否广告页」这个页面级证据传进安全闸门
（`isSafeCandidate(area, cy, adSignal)`），由它决定用哪套安全带。
页面级证据只在**同一轮扫描**内有效，不会跨轮残留。

> 另外顺手清掉了 `adTexts` 里几条过宽的词（「点击下载」「立即下载」「点击跳转详情页」），
> 它们会误放宽正常页面，已删除。

## v3.0：全面防误触（面向老人，宁可漏跳，绝不误触）

用户反馈：打开抖音时**误触右上角的搜索**；打开全屏搜索时也会误触。
这是比「漏跳」严重得多的问题 —— 所以 v3.0 把「不误触」放在「多跳过」之前。

### 两个根因

**① 误触 1「打开抖音误触右上角搜索」—— 观察窗口被广告 SDK 窗口"接管"了。**

抖音的「跳过」在右上角，而主页的**搜索图标也在右上角**，位置高度重合。
更糟的是：开屏广告常由广告 SDK 渲染在**独立窗口**里，那个包名一到，
v2.1 会把观察**接管**到广告 SDK 包上；等广告消失、抖音主界面回来时，
又被当成一次新的前台切换 —— 于是**在正常界面上重新开了一个观察窗口**，
就去点搜索图标了。

修法：观察一旦开始就**锚定**在那个应用上，任何其它包名都不接管、不重启。
反正我们是遍历全部窗口扫描的，广告窗口照样能被扫到，根本不需要换锚点。

**② 误触 2「打开全屏搜索也会误触」—— 同应用内换界面被当成了"重新启动"。**

v2.1 观察结束（清空 `watchPkg`）后，同一应用内的**任何**窗口变化
都会被判成「开始监听」而**重新开一轮观察**。所以在抖音里点开全屏搜索，
就又扫起来了。

修法：区分「真正切换了应用」和「同一应用内部换界面」——
后者在没在观察时一律忽略。并加一层**冷却**：刚从同一个应用观察完、
且期间没回过桌面，就不允许再开一轮。

### 四道防误触闸门

| 闸门 | 作用 |
|---|---|
| **稳健模式**（`safeMode`，默认开） | 候选必须**小**（面积 ≤ `safeMaxArea`）且落在屏幕**顶部带或底部带**内（`safeTopBand`/`safeBottomBand`）。屏幕正中是正文/输入区，一律不点 |
| **必须有文字依据** | 稳健模式下只认**文字命中**（「跳过」「跳过广告」…），纯靠控件 ID 命中的图标候选不予点击 —— 抖音搜索图标就是纯图标 |
| **点击前复核位置**（`verifyBeforeTap`，默认开） | `dispatchGesture` 是**异步**的，手势落下时界面可能已经变了。所以点击前复核目标此刻仍在原位（容差 8px）、且那个坐标上确实还是它。不满足就放弃 |
| **开屏期 + 冷却** | 只在回到前台后 `splashWindowMs`（默认 6 秒）内扫描；同一应用两次观察之间冷却 `episodeCooldownMs`（默认 60 秒） |

此外，点击**优先用 `ACTION_CLICK` 而不是坐标手势** ——
`ACTION_CLICK` 直接作用在那个节点上，不受界面切换导致的坐标位移影响，
从根上避免「点到的其实是另一个控件」。

> **代价**：这些闸门会让「漏跳」的概率上升（某些设计特殊的开屏页可能跳不掉）。
> 这是刻意的取舍 —— 对老年用户来说，「没跳过」只是多点一下，
> 而「误触搜索/误点广告」会让人不知所措。如果你更在意跳过率，
> 可以在应用里把「稳健模式」关掉。

## v2.1 的改动（修「有时能跳、有时跳不掉」）

QQ音乐 出现时灵时不灵。这不是规则问题（规则是固定的），而是**竞态**：

| 缺陷 | 修法 |
|---|---|
| **观察窗口被无关窗口掐断** | 原实现收到任何 `TYPE_WINDOW_STATE_CHANGED` 就不判包名直接 `endWatch()`；广告常在观察被掐断**之后**才渲染出来。改为纯函数 `decideForeground()` 显式区分各种情况 |
| **扫描完全依赖事件驱动** | 广告若是纯图片/视频渲染可能一个事件都不发。新增**主动轮询** `pollIntervalMs`（默认 250ms） |

## v2.0 的改动

v1.0 的根本缺陷：只用 `getRootInActiveWindow()` 扫描**当前活动窗口**，
而开屏广告常由广告 SDK 渲染在**独立窗口**里 ⇒ QQ音乐 这类永远扫不到。
v2.0 改用 `getWindows()` 遍历**全部窗口**，并加入候选打分、剔除大块广告容器、
诊断快照、盲点兜底等。

候选打分权重（见 `SkipEngine.java`）：精确文字 +80、控件 ID +60、强关键词 +40、
可点击 +25、可点击祖先深度1 +15/深度2 +8、小面积 +20、靠上 +12、靠右 +10、
靠下 +8、含倒计时数字 +8。**低于 30 分的候选一律不点**；
有安全候选时只从安全候选里挑。

### 列表里找不到「跳过广告」怎么办

这是最常见的问题，按下面顺序排查（应用里已经放了对应按钮）：

**① 「已下载的服务」要展开。**
绝大多数手机的无障碍页面里，本应用不在最外层列表，而是折叠在
**「已下载的服务」** 或 **「已安装的服务」** 这一项里面，需要再点进去一层。
一直往下翻，通常在列表最底部。

**② 直接点应用里的快捷入口。**
首页状态卡片上有两个描边按钮：

- **找不到「跳过广告」？点这里直达开关** —— 直接跳到本服务自己的开关页，不用在大列表里翻。
- **开关是灰的？点这里解除受限设置** —— 见第 ③ 条。

**③ Android 13 及以上：解除「受限设置」。**
用数据线/浏览器等方式**侧载安装**的应用，Android 13 起默认被标记为「受限设置」，
无障碍开关会是**灰色不可点**，并提示「受限制的设置，出于安全考虑，此设置当前不可用」。

解除方法（任一即可）：

- 点应用里的 **开关是灰的？点这里解除受限设置**，进入应用信息页，
  点**右上角三点菜单** → **允许受限设置**；
- 或者：设置 → 应用 → 跳过广告 → 右上角菜单 → 允许受限设置；
- 或者：用 adb 执行
  ```
  adb shell pm set-app-links --package com.lbx.skipad 0 all
  adb shell appops set --uid com.lbx.skipad ACCESS_RESTRICTED_SETTINGS allow
  ```

解除后再回无障碍页面，开关就能点开了。

**④ 部分国产系统会「隐藏」非白名单无障碍服务。**
个别 ROM（尤其开了「纯净模式」「安全模式」的机器）只显示系统认证过的无障碍应用。
此时需要在 **设置 → 安全 → 更多安全设置** 里关闭纯净模式，
或暂时关闭手机管家类的拦截功能，重新打开一次本应用。

**⑤ 确认确实装上了。**
桌面应该有蓝色图标「跳过广告」，点开能正常看到界面。
如果桌面没有图标，说明 APK 没装成功，重新安装一次。

## 三、使用

开启后不需要任何操作。正常打开其他 App，开屏广告出现时会被自动点掉，
并伴随一次轻微震动和一行「已跳过广告」提示。

### 界面上的开关

- **启用跳过功能** —— 总开关，关掉后服务完全不工作。
- **跳过时震动** —— 每次成功跳过震一下。
- **跳过时提示** —— 屏幕下方显示一行提示。
- **监听所有应用** —— 默认开启。关掉后只监听 `编辑规则` 里单独配置过的应用。
- **稳健模式（推荐开启）** —— v3.0 的防误触主力开关。只在小按钮、位于屏幕顶部/
  底部、且有文字依据时才点。**给老人用时务必保持开启。**
- **抓取诊断快照** —— 跳不掉时记下当前界面文字，便于排查（默认开）。
- **点击前复核位置** —— 防止广告消失后点击落到同一位置新出现的图标上
  （抖音搜索就是这个原因被误触的，默认开）。
- **盲点兜底** —— 完全找不到按钮时盲点右上角一次（默认**关**，误触风险最高）。
- **卡住自救（按返回键）** —— v3.4 新增，默认**开**。确认当前是广告页、却怎么都跳不掉时，
  等 3.5 秒自动按一次返回键结束广告。这是「卡在启动页退不出」的出路，普通界面绝不触发。
- **查看日志** —— 最近 60 次跳过记录（时间 / 应用 / 命中原因）。
  开头那条「服务自检」用来判断服务有没有被系统拉起。
- **查看诊断** —— 开屏早期的界面文字快照，可用于把漏掉的按钮配进规则。
- **恢复默认规则** / **清空日志** / **清空诊断**。

### 字段说明

| 字段 | 作用 |
|---|---|
| `watchAll` | 是否监听所有应用。`false` 时只监听 `apps` 里列出的、且 `enabled` 为 true 的应用 |
| `scanIntervalMs` | 扫描间隔（毫秒），范围 40–2000。越小响应越快、越耗电，默认 100 |
| `maxTextLen` | 关键词包含匹配的长度上限，范围 2–20。**调大更容易命中，但也更容易误伤**，默认 8 |
| `maxWaitMs` | 观察窗口时长（毫秒），范围 2000–120000。超过就停止扫描，默认 15000 |
| `retryLimit` | 一次启动内最多尝试点击几次，范围 1–50，默认 8（v2 调大，能处理「广告分两段」） |
| `continueAfterSkip` | 跳过一次后是否继续找下一个跳过后，默认 `false` |
| `blindTapEnabled` | **盲点兜底**：完全找不到任何候选时，按下面的坐标盲点一次。默认 `false` |
| `pollIntervalMs` | 主动轮询间隔（毫秒），范围 80–2000，默认 250。即使没有任何无障碍事件也按此周期扫描 —— 修「有时能跳、有时不行」的关键 |
| `blindTapX` / `blindTapY` | 盲点位置的**归一化坐标**（0~1，相对屏幕）。默认 `0.86, 0.07` 即右上角 |
| `safeMode` | **稳健模式**（v3.0 默认 `true`）。开启后候选必须小、且落在安全带内、且有文字依据才点 |
| `splashWindowMs` | 开屏期时长（毫秒），范围 1000–60000，**默认 12000**（v3.4 由 6000 放宽，弱网下广告常在 8~12 秒才盖上来）。只在回到前台后这段时间内扫描 |
| `episodeCooldownMs` | 同一应用两次观察之间的冷却（毫秒），范围 1000–600000，**默认 8000**（v3.4 由 60000 收紧，且**只对"上一轮真的跳成了"生效**）。防止把扫描带进正常界面 |
| `verifyBeforeTap` | 点击前复核目标是否仍在原位（v3.0 默认 `true`），防异步点击穿透 |
| `safeMaxArea` | 稳健模式下候选的最大面积占比，范围 0.01–1.0，默认 0.12 |
| `safeTopBand` / `safeBottomBand` | 稳健模式的安全带（归一化纵坐标）。默认 `0.30` / `0.75`，即只有屏幕顶部 30% 与底部 25% 允许点击 |
| `shakeAware` | **摇一摇广告放宽**（v3.1 默认 `true`）。页面上出现 `adTexts` 特征文案时，判定为广告页并改用下面一组更宽的安全带 |
| `shakeBlindTap` | 广告页上也允许**无文字依据**的候选（v3.1 默认 `false`）。关着时只放宽位置和面积，仍要求文字依据 |
| `adTopBand` / `adBottomBand` | 广告页安全带（归一化纵坐标），默认 `0.60` / `0.75`。`adTopBand` 钳制到 `safeTopBand`–0.80，`adBottomBand` 钳制到 0.30–`safeBottomBand`（只能往上挪，扩大可点范围），且上下带间保证至少 0.05 走廊 —— 中间走廊一律不点 |
| `adMaxArea` | 广告页候选的最大面积占比，默认 `0.25`（普通页 0.12），钳制到 0.01–0.55 |
| `adTexts` | 摇一摇/摇动类**广告特征文案**（v3.1；v3.4 补 `互动广告`、`开屏广告`、`跳过并关闭`）。命中不代表要点击，只表示「这确实是广告页」，从而放宽安全带，也是「卡住自救」的判断依据 |
| `fgPollMs` | **前台轮询间隔**（v3.4，默认 `700`，范围 150–3000）。与无障碍事件完全无关的看门狗，自己读当前前台应用 —— **这是「开机即生效」的关键**。观察期内自动减半，最快 220 |
| `firstScreenExit` | v3.3 的「首屏切走收手」（v3.4 默认 **`false`**）。开着会把「启动页 → 广告页」误判成「用户已离开」，在广告刚盖上来时收手 |
| `unsafeRejectLimit` | 出现不安全候选几次后才结束观察（v3.4，默认 `3`，范围 1–20）。v3.3 是 1 次就收，容易被广告页里的正常按钮骗走 |
| `backKeyFallback` | **卡住自救**（v3.4 默认 `true`）。确认当前是广告页、且 `backKeyDelayMs` 内怎么都跳不掉时，自动按一次返回键结束广告。普通界面绝不触发 |
| `backKeyDelayMs` | 确认广告页后等多久才按返回键（v3.4，默认 `3500`，范围 800–20000） |
| `skipTexts` | **精确匹配**：控件文字去掉空白和标点后与此完全相同才命中，+80 分 |
| `strongTexts` | **包含匹配**：文字压缩后长度 ≤ `maxTextLen` 且包含此关键词即命中，+40 分 |
| `denyTexts` | 黑名单。完全相等，或黑名单词 ≥3 字且被包含时，**一律不点** |
| `skipIds` | 控件 ID 规则，见下，+60 分 |
| `excludeApps` | 永不监听的应用（桌面、设置、安装器、系统 UI 等） |
| `apps` | 针对单个应用的覆写：`enabled` 是否监听、`extraTexts`/`extraIds` 追加规则 |

### 关于「盲点兜底」

默认关闭，因为**盲点有误点风险**（它不看界面内容，纯粹按坐标点一下右上角）。
什么时候值得开：某个 App 明明有开屏广告、日志和诊断快照里却**完全找不到任何按钮**
（广告是纯图片/视频、按钮用自绘控件），这时盲点是唯一手段。

开了之后如果发现误点，把 `blindTapX`/`blindTapY` 调到真正跳过按钮的位置即可
（用「查看诊断」看界面尺寸，再算归一化坐标）。

### 控件 ID 的三种写法

Android 的控件 ID 长这样：`com.tencent.mm:id/skip_btn`，冒号后面是 id 名。

| 写法 | 含义 | 例子 |
|---|---|---|
| `*:xxx` | 只比较 `/` 后面的 id 名，支持 `*` 通配（**推荐**） | `*:*skip*` 命中 `skip`、`skip_btn`、`btn_skip`、`splash_skip_view` |
| 含 `/` | 与完整 ID 通配匹配 | `com.tencent.mm:id/skip*` |
| 其它 | 与 id 名通配匹配 | `skip_btn` 只命中名字正好是 `skip_btn` 的 |

通配符 `*` 表示任意长度字符（含空）。

### 某个 App 跳不掉怎么办（v2 起就有的工具）

**第 0 步：先看「查看诊断」。** 这是 v2 最有力的工具。
保持「抓取诊断快照」开启（默认开），然后打开那个跳不掉广告的 App，
**等广告自己结束、进入主界面后**，回到本应用点「查看诊断」。

快照会在**开屏早期**（启动后约 0.4~6 秒，也就是广告还在屏幕上时）自动抓取，
这样记下来的才是广告界面本身 —— 如果等到 15 秒超时才抓，广告早消失了，
得到的只会是 App 主界面。快照里会列出该界面**所有文字和可点击控件**，
包括按钮的真实文案和控件 ID（可长按复制）。

> 每条快照开头都会标明「时机」：`开屏早期（广告应该还在屏幕上）`
> 是你要看的那条；若显示 `超时兜底（可能已进入主界面）`，说明那次没赶上，
> 重新打开一次那个 App 再看。

然后按日志分情况处理：

1. **日志里压根没记录** → 说明没找到按钮。
   - 打开诊断快照，找找有没有像「跳过」的按钮，把它的文字加到 `skipTexts`；
   - 顺带把 `maxTextLen` 临时调到 **10~12**；
   - 如果诊断里**连一个按钮都没有**（纯图片广告），才考虑开「盲点兜底」。
2. **有记录但广告还在** → 说明点错了位置。
   - 把被误点的文字加进 `denyTexts`；
   - 或把 `maxTextLen` 调小；
   - 极端情况下把该应用加进 `excludeApps`。
3. **点进了广告（跳转到广告页）** → 把 `denyTexts` 补上误点文字，
   并把该应用加进 `excludeApps` 先停掉，避免反复误触。

### 误伤了正常按钮怎么办（v3.0 重点，针对老年用户）

v3.0 已经内置了四道防误触闸门（见开头），默认就挡住了绝大多数误触。
如果**仍然**点错，按优先级依次尝试：

1. **确认「稳健模式」是开着的**（应用首页的开关，默认开）。
   实测中抖音右上角搜索被误触，正是靠它 + 「点击前复核位置」挡住的。
2. 把误点文字加入 `denyTexts`；
3. 把 `maxTextLen` 调小（比如调到 4~5），只保留「跳过」这类核心词；
4. 把该应用加进 `excludeApps`（**最保险**：完全不监听这个 App）；
5. 关掉 `watchAll`，只在 `apps` 里逐个添加你确实想跳广告的应用。

> **给老人用的建议配置**：保留「稳健模式」和「点击前复核位置」开启，
> 关掉「盲点兜底」（它是唯一会"盲点"的功能，误触风险最高）。
> 如果某个 App 老是误触，直接把它加进 `excludeApps` —— 那个 App 就不跳了，
> 但绝不会再点错。对老人来说这个取舍通常更划算。

### 反过来：太保守、该跳的没跳

稳健模式为了防误触会牺牲一部分跳过率。如果发现某个 App 的开屏广告
明明有「跳过」按钮却没被点：

- 先在「查看诊断」里确认那个按钮确实被识别成了候选
  （看「最近扫描」那行有没有「已拦下不安全候选」）；
- **如果页面是摇一摇/摇动手机类广告**：先确认「摇一摇广告放宽」是开着的
  （应用首页有显示，v3.1 默认开）。若仍跳不掉，说明这颗按钮连放宽后的安全带
  也没进去，可以调大 `adTopBand` / `adMaxArea`；
- 若是被安全闸门拦下的，可以适当放宽：把 `safeMaxArea` 调大（如 0.20）、
  把 `safeTopBand` 调大（如 0.40）以扩大可点区域；
- 实在需要，再考虑关掉「稳健模式」—— 但请清楚这会显著提高误触风险。

## 五、工作原理

```
应用切到前台
      ↓
判断是否在监听范围（不在 excludeApps、且 watchAll 或已单独配置）
      ↓  是
【v3.0 防误触】先过前台切换决策 decideForeground()：
      · 正在观察中？→ 任何其它包名都不接管、不重启（锚定原应用）
      · 同一应用内换界面？→ 没在观察时一律忽略
      · 刚从同一应用观察完且没回过桌面？→ 冷却中，忽略
      ↓  允许开始时
开启观察窗口（稳健模式下取 splashWindowMs=12 秒）
      ↓
【v3.4 看门狗】与事件无关：fgPollMs=700ms 主动读一次当前前台，
即使一条无障碍事件都没收到也能开始观察（观察期提速到最快 220ms）
      ↓
【v3.1 第一趟：判广告页】遍历窗口控件树，只要有一处文字/描述命中 adTexts
（摇一摇、摇动手机…）就标记 adSignal = true —— 这是**页面级证据**，不产生候选
      ↓
【v2 核心】用 getWindows() 遍历**全部窗口**的控件树（排除桌面/设置/系统UI窗口），
逐个比对：
      · 控件 ID 命中 skipIds？              → +60
      · 文字去掉空白标点后与 skipTexts 完全相同？ → +80
      · 文字很短（≤ maxTextLen）且含 strongTexts？ → +40
      · 命中 denyTexts 黑名单？→ 直接放弃
      · 是输入框？→ 直接放弃
      · 面积超过窗口 55%？→ 直接放弃（是广告容器，不是小按钮）
      ↓
对全部候选打分（可点击 +25、小面积 +20、靠上 +12、靠右 +10、
含倒计时 +8、可点击祖先越近分越高），取最高分者（有安全候选时只从安全候选里挑）
      ↓  最高分 ≥ 30
【v3.0/v3.1 稳健模式安全闸门】候选必须：
      · 面积 ≤ safeMaxArea（默认 0.12）；**广告页放宽到 adMaxArea（0.25）**
      · 落在安全带内（顶部 30% 或底部 25%）；**广告页放宽到顶部 60%**（底部不动），
        中间走廊 60%~75% 一律不点 —— 用的是 isSafeCandidate(area, cy, adSignal)
      · 有文字依据（纯 ID 命中的图标不点）；**广告页且开了 shakeBlindTap 时才免除**
      ↓  通过
【v3.0 点击前复核】目标此刻是否仍在原位（容差 8px）、
该坐标上是否确实是它 —— 不满足就放弃
      ↓
点击：优先 ACTION_CLICK（直接作用在节点，不受坐标位移影响），
      其次坐标手势，最后向上找可点击父控件
      ↓
震动 + 提示 + 记一条日志
      ↓  一直没命中，且确认是广告页
【v3.4 卡住自救】广告页已持续 backKeyDelayMs=3.5 秒仍跳不掉
（按钮是纯图片/视频，控件树里根本没节点）→ 自动按一次返回键结束广告
      ↓  从未命中且开启了盲点
按 blindTapX/Y 归一化坐标盲点一次（默认关）
      ↓  超时仍没找到
静默退出，若开了诊断则存一份界面快照
```

### 为什么这样设计

**只在启动窗口内工作。** 开屏广告只可能出现在应用启动的最初几秒。
过了这个窗口就完全停止扫描，所以不会在你正常刷微信、看视频时误点。
v3.0 更把稳健模式下的窗口收紧到 `splashWindowMs`（v3.4 起默认 12 秒 ——
弱网下「启动页 → SDK 拉素材 → 广告盖上来」常要 8~12 秒，6 秒窗口会在广告出现前关掉）。

**不靠事件也能醒过来。** （v3.4）整套逻辑原本完全由无障碍事件驱动，
开机时 ROM 吞掉首批事件就永久失效。现在有一个 `fgPollMs` 看门狗主动读前台，
事件只是"加速信号"，不是"唯一信号"。

**扫全部窗口，而不只是活动窗口。** 这是 v2 最重要的修正。
开屏广告经常由广告 SDK 渲染在独立窗口里，`getRootInActiveWindow()`
根本看不到它 —— v1 在 QQ音乐 上失效就是这个原因。

**观察窗口锚定，不随广告 SDK 窗口漂移。** 这是 v3.0 防误触的关键。
抖音的「跳过」与主页搜索图标都在右上角，一旦观察窗口被广告 SDK 的包名
"接管"，等广告消失后就可能在抖音主界面上继续扫描并点中搜索图标。
现在观察只锚定用户实际打开的那个应用，广告窗口靠多窗口扫描覆盖。

**点击前复核 + 优先 ACTION_CLICK。** `dispatchGesture` 是异步的，
手势落下时界面可能已经换了。这两个措施一起，从机制上消除
「点到的其实是同一位置新出现的另一个控件」。

**只在小按钮、靠边位置、且有文字依据时才点。** 跳过按钮一定满足这三个特征，
而正常界面里像「搜索」「更多」这类图标通常不满足全部三条。
用这三个约束换掉一部分跳过率，换取「不会点错」。

**摇一摇广告：靠页面证据有条件放宽，而不是整体拆掉防线。** （v3.1）
这类广告的跳过按钮位置偏下（被顶部 logo 挤走），且常是纯图片。
整体放宽安全带 = 全屏可点，会原样放回误触；所以改成
「**页面上确实出现摇一摇类特征文案**」才启用更宽的安全带，
且放宽后的安全带**仍有不可点击的中间走廊**，面积上限也仍有钳制。
代价是某些不含这些特征词的摇一摇广告依然跳不掉 —— 宁可漏放宽。

**长度限制（`maxTextLen`）。** 「点击跳过，查看更多精彩内容」这种长句里也含「跳过」，
但它显然不是跳过按钮。压缩后超过 8 个字就一律不做包含匹配，从源头掐掉大部分误伤。

**黑名单机制。** 「跳过此步骤」「跳过引导」「跳过教程」这类按钮点下去会真的跳过流程，
所以宁可漏点也不点。

**候选打分而不是先到先得。** 一个开屏页里同时出现「跳过」「立即查看」「5s」很常见，
按分数挑最像按钮的那个（精确文字 + 位置 + 大小 + 可点击性），比"第一个命中就点"稳得多。

**剔除大块容器。** 面积占窗口 55% 以上的节点只可能是广告容器本身。
点它就会跳转到广告落地页，所以从候选里直接排除。

**点击顺序。** 很多开屏页整个广告区域都是可点击的（点了就跳广告落地页），
而「跳过」文字只是它的子节点。如果一上来就找可点击的父控件，很可能点到广告本身，
所以优先用文字节点自己的坐标精准点击。

## 六、隐私

- 没有任何网络权限，**Manifest 里连 INTERNET 都没申请**，物理上不可能联网。
- 只读取无障碍服务可见窗口的控件树，不读取其他应用的数据。
- 跳过记录与诊断快照只存在手机本地，随时可清空。
- 唯一申请的权限是 `VIBRATE`（震动）。

可以在应用设置里查看：本 APK 申请的权限只有 1 项 —— `android.permission.VIBRATE`。

## 七、常见问题

**Q：装了没反应？**
A：九成是无障碍服务没开，或被杀后台了。回到应用看顶部是不是绿色「● 已启用」，
并对照第二节的品牌补充设置。

**Q：无障碍列表里根本找不到「跳过广告」？**
A：见第二节「列表里找不到「跳过广告」怎么办」。
最常见两种：一是它被折叠在 **「已下载的服务」** 里面；二是 Android 13+
对侧载应用默认「受限设置」，开关是灰的，需要去应用信息页右上角菜单里放行。
应用首页已经为这两种情况各放了一个快捷按钮。

**Q：显示已启用，但某些 App 还是跳不掉？**
A：v2 给了专门的排查工具。按这个顺序来：

1. 保持「抓取诊断快照」开启，重现一次那个 App 的开屏；
2. 回到本应用点「查看诊断」，看那张界面上到底有哪些文字和按钮；
3. 把真正的跳过按钮文字加进 `skipTexts`；
4. 如果诊断里**一个按钮都没有**（纯图片/视频广告），才考虑开「盲点兜底」。

**Q：会不会误触到 App 里的正常按钮？（v3.0 重点）**
A：v3.0 就是专门为这个问题做的。四道闸门：
① **稳健模式**要求候选必须是小按钮、且位于屏幕顶部/底部、且有文字依据；
② **点击前复核**确保目标此刻仍在原位，防止点击穿透到同位置新出现的图标；
③ **观察窗口锚定在原应用**，不随广告 SDK 窗口漂移，
   避免在正常界面上重新扫描；
④ **同应用内换界面不再重开观察**，并加冷却（v3.4 起 8 秒，且只对上一轮真跳成了生效）。

抖音的「打开时误触右上角搜索」和「打开全屏搜索误触」这两例，
正是靠 ①②③④ 一起挡住的。

**Q：为了防误触，是不是有些广告就跳不掉了？**
A：是，这是刻意的取舍。稳健模式会让一部分设计特殊的开屏页跳不掉
（例如跳过按钮做得很大、或位于屏幕正中的）。
对老年用户来说，「没跳过」只是多点一下，而「点错」会让人不知所措。
如果你更在意跳过率，可以在应用里关掉「稳健模式」；
也可以只放宽参数（`safeMaxArea`、`safeTopBand`）而不是整个关掉。

**Q：摇一摇广告跳不掉怎么办？（v3.1）**
A：v3.1 已经针对这类广告做了放宽：只要页面上出现「摇一摇 / 摇动手机」等特征文案，
就判定为广告页，改用更宽的安全带（顶部 60%，面积上限 0.25）。
若仍然跳不掉，按顺序检查：

1. 确认「摇一摇广告放宽」是**开着**的（应用首页有这一行状态，默认开）；
2. 去「查看诊断」，看那个广告页上到底有没有 `adTexts` 里的文案 ——
   若完全没有（比如只有一张图、连提示文字都是图片），放宽不会触发，
   这时只能调大 `safeTopBand` 或考虑关掉「稳健模式」；
3. 若是纯图片的「跳过」且文字依据过不了，才考虑开 `shakeBlindTap`
   （注意：这会让广告页上的纯图标候选也可点，风险略高）。

**Q：重启手机以后跳广告就不灵了，要手动关开一次无障碍开关才恢复？（v3.4 已修）**
A：这是 v3.3 及以前的通病，两个原因一起造成：

1. 整套逻辑**完全靠无障碍事件驱动**。开机时系统很早就拉起服务，那一刻 ROM 可能把首批事件
   全部吞掉，而之后再没有任何机制主动看一眼 —— 服务活着但一动不动。
   v3.4 加了 `fgPollMs`（默认 700ms）前台看门狗，自己读当前前台应用，收不到事件也能开始观察。
2. 部分 ROM 在开机拉起服务时给一个「事件类型都为空」的 `AccessibilityServiceInfo`，
   服务在跑却收不到事件。v3.4 在 `onServiceConnected()` 里把 info 原样写回重登记一次
   （1500ms 后再补一次）。

如果升级后仍不灵，先做一件事：打开「查看日志」，看**最上面有没有**这一行
「服务自检 · v3.4 已连接 · 总开关开 · 扫描线程就绪 · 前台轮询已启动」。
**没有这一行** = 系统压根没拉起服务，请到「电池 → 应用启动管理」里给「跳过广告」
开**自启动 + 允许后台活动**；**有这一行却不跳** = 是规则或界面问题，去查诊断快照。

**Q：卡在某个应用的开屏广告进不去、返回键也退不出？（v3.4 已修）**
A：这是超级课程表那类「京东开屏广告盖满全屏」的场景，四个原因：

1. 观察窗口只有 6 秒，而广告在弱网下常要 8~12 秒才盖上来 —— 窗口在广告出现前就关了。
   现在默认 **12 秒**。
2. v3.3 的「首屏切走收手」把「启动页 → 广告页」当成「用户已离开」而提前收手 ——
   正好是最该干活的一瞬。v3.4 把 `firstScreenExit` 默认**关掉**。
3. 「用户已离开」分支少了 `return`，在桌面上又重开一轮观察（还会扫桌面）。
   已修，离开就到此为止。
4. 跳过按钮是纯图片 / 视频覆盖层，控件树里根本没这个节点，只能干等。
   现在有**卡住自救**：确认是广告页且 3.5 秒内跳不掉，就自动按一次返回键结束广告。

**Q：升级到 v3.4 要卸载重装吗？**
A：不用。同一个签名密钥，直接覆盖安装，规则设置会保留。
（从 v1.0 一路升上来也是同一个签名。）
注意 v3.4 改了默认值（`splashWindowMs` 12 秒、`episodeCooldownMs` 8 秒等），
如果你之前**手动改过规则 JSON**，旧值会保留在你自己的配置里 ——
想用新默认值，点一次「恢复默认规则」即可。

**Q：会不会把我微信聊天里的内容传出去？**
A：不会。没有网络权限，代码里也没有任何网络调用。

**Q：费电吗？**
A：只在应用启动后的几秒内工作（稳健模式下 6 秒），其余时间完全休眠，日常使用几乎无感。

**Q：能跳过应用内的弹窗广告、信息流广告吗？**
A：不能。本应用只处理**开屏广告**，这也是它安全的原因 ——
精准限定在启动窗口，代价是不处理其他类型的广告。

**Q：卸载后服务还开着吗？**
A：卸载会自动解除。若先手动关闭，去 设置 → 无障碍 → 已下载的服务，关掉「跳过广告」。

## 九、源码与重新编译

`源码/` 是一个标准的 Android 工程，可以直接用 Android Studio 打开；
也可以用附带的脚本编译，**不需要安装 Android Studio 或 Gradle**：

```powershell
pwsh -File 源码/build.ps1     # 编译出 APK
pwsh -File 源码/test.ps1      # 跑 210 项逻辑自测
```

构建流程：

```
aapt2 compile（编译资源）
   → aapt2 link（链接资源 + 生成 R.java）
   → javac --release 11（编译 Java）
   → d8（转 Dalvik 字节码）
   → aapt add（把 classes.dex 塞进 APK）
   → zipalign -p 4（对齐）
   → apksigner（签名）
```

> 为什么用 `aapt add` 而不是重写 zip：`resources.arsc` 必须以**未压缩 + 4 字节对齐**
> 的方式存放（targetSdk 30+ 的硬性要求），重写 zip 会破坏这个状态。
> `aapt add` 只追加新条目，不动原有条目。

### 路径含中文时的处理（已经自动搞定）

`aapt2` 在 Windows 上有个已知缺陷：**无法打开路径里含非 ASCII 字符的文件**。
把本工程放在 `D:\手机跳广告（安卓版）\源码` 这类路径下时，直接调用会报：

```
aapt2 compile --dir <带中文的路径>
error: failed to open directory: 系统找不到指定的文件。 (2).
```

`build.ps1` 已内置规避：**检测到工程路径含中文时，自动把构建过程搬到
`%TEMP%` 下的纯 ASCII 临时目录里执行，完成后再把 APK 和密钥库拷回工程目录。**
对你完全透明，产物位置不变。构建时你会看到一行提示：

```
检测到工程路径含中文：
  D:\手机跳广告（安卓版）\源码
aapt2 不支持非 ASCII 路径，本次构建将在临时目录中进行：
  C:\Users\...\Temp\skipad-build-xxxxxxxxxx
```

（其它工具 javac / d8 / zipalign / apksigner 都能正常处理中文路径，
只有 aapt2 有此问题。）

### 自测覆盖

`test.ps1` 会在桌面 JVM 上运行 282 项断言，不需要手机、不需要模拟器：

- 规则 JSON 解析与边界钳制（`scanIntervalMs` 下限 40、`maxTextLen` 上限 20、
  `blindTapX/Y` 钳到 0~1 等）
- 文本归一化（去空白、去标点、大小写、全角空格、是否有数字）
- 正向命中：13 种真实跳过按钮写法（「跳过5」「5s 跳过」「跳过|5」「Skip Ad」…）
- 反向拒绝：27 个常见正常按钮（「同意并继续」「一键登录」「以后再说」…）零误伤
- 黑名单拦截：「跳过此步骤」「跳过引导」「跳过学习」等
- 控件 ID 通配匹配（`*:*skip*`、全限定写法、`glob` 边界）
- **v2 候选打分**：单项权重、位置加成（右上 > 正中）、小面积加成、
  可点击祖先深度优劣、倒计时加成、大容器低于阈值、`pickBest` 选优与全差返回 null
- **v2 matchKind**：精确=2 / 包含=1 / 不匹配=0 / 黑名单=0
- 监听范围判定（桌面、设置、安装器不监听）
- **v3.0 前台切换决策**：decideForeground 的 FG_SAME / FG_KEEP / FG_START /
  FG_IGNORE 全分支，含两个误触场景的回归用例
  （观察中不接管广告 SDK 窗口；同应用换界面不再重开观察）与冷却逻辑
- **v3.0 稳健模式闸门**：isSafeCandidate 的面积上限、安全带边界、
  面积未知时的处理、关掉稳健模式后的放行
- **v3.0 安全参数钳制**：splashWindowMs/episodeCooldownMs 下限、
  safeMaxArea 上限、安全带上下限
- **v3.0 pickBest 安全优先**：安全候选优先于高分不安全候选、
  只剩不安全候选时仍返回（供服务层拦下并记录）
- **v3.1 摇一摇广告特征识别**：isAdSignal 对「摇一摇」「摇一摇跳转详情」
  「摇动手机」的命中，以及对「跳过」「设置」、空串、null 的不命中（含带标点变体）
- **v3.1 广告页放宽安全带**：isSafeCandidate(area, cy, adSignal) 三参版本 ——
  同一位置在非广告页仍被拦下（v3.0 行为不变的回归用例）、在广告页放行；
  0.60 / 0.80 边界；60%~80% 中间走廊两侧的拦截与放行；
  面积 0.12~0.25 只在广告页放行、超 0.25 仍拦；关掉 shakeAware 后完全回到 v3.0；
  二参重载等价于 adSignal=false
- **v3.1 广告页安全带钳制**：adTopBand 上限 0.80、adMaxArea 上限 0.55、
  上下带之间保证至少留 0.05 走廊
- **v3.1 特征词收窄**：adTexts 不含「下载」「立即」这类正常页面也会出现的词
- **v3.4 新增参数默认值**：`fgPollMs=700`、`firstScreenExit=false`、`unsafeRejectLimit=3`、
  `backKeyFallback=true`、`backKeyDelayMs=3500`，以及 `splashWindowMs` 由 6000 改为 12000、
  `episodeCooldownMs` 由 60000 改为 8000
- **v3.4 新增参数钳制**：`fgPollMs` 150–3000、`unsafeRejectLimit` 1–20、
  `backKeyDelayMs` 800–20000 的上下限
- **v3.4 冷却只对「上一轮真跳成了」生效**：`lastEpisodeHit=true` 时同应用重复打开走 FG_IGNORE，
  `lastEpisodeHit=false` 时必须 FG_START（否则开机那一下没跳成，之后怎么开都不跳）
- **v3.4 开屏广告角标识别**：`adTexts` 命中「互动广告」「开屏广告」，
  且**不含裸词「广告」**（正常页面太常见，收了会把全屏放宽）
- **v3.4 超级课程表单独规则**：`com.tencent.pocket` 的 extraTexts / extraIds 生效
- **v3.4 skipIds 补倒计时角标**：`*:*countdown*`、`*:*ad_time*` 命中
- 逐应用覆写、非法 JSON 容错、null 入参不崩

打分逻辑之所以能在桌面 JVM 上测，是因为 `Cand` 的打分只依赖纯数据字段
（`idHit`/`exactHit`/`areaRatio`/`nx`/`ny` 等），不碰 `AccessibilityNodeInfo`。
