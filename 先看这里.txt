【v3.4 修了什么（开机即生效 · 卡住自救）】
 你反馈了两件事：
   ① "有时候会出现开启手机以后无法启动这个跳过广告的操作。"
   ② "如果这个手机开启以后处在一个应用界面里面，有可能无法退出，
       均卡在超级课程表的这个启动界面无法进入。"

 ── A. 开机以后跳广告不灵了 ──

 根因1：整套逻辑纯事件驱动。v3.3 的所有动作都靠系统发无障碍事件来触发。
   开机时系统很早就拉起服务，那一刻 ROM 常把首批事件全部吞掉，之后
   再没有任何机制主动看一眼 —— 服务"活着但一动不动"，直到你手动
   关开一次开关才恢复。
   修法：新增一个与事件完全无关的看门狗 fgPollMs（默认 700 毫秒），
   自己按周期读当前前台应用，喂给和事件路径相同的决策函数；观察期内
   自动提速到最快 220 毫秒。收不到任何事件也能开始干活 —— 这是
   "开机即生效"的关键。

 根因2：服务连接后没重新登记无障碍能力。部分 ROM 在开机拉起服务时给
   一个"事件类型/flags 都为空"的 info，服务在跑却收不到事件。
   修法：连上后把当前 info 原样写回重登记一次，1500 毫秒后再补一次。

 另加一条「服务自检」日志，用来一眼分清故障位置：
   打开「查看日志」，最上面没有
     「服务自检 · v3.4 已连接 · 总开关开 · 扫描线程就绪 · 前台轮询已启动」
   = 系统压根没把服务拉起来（去查电池优化 / 自启动权限）；
   有这一行却还是不跳 = 规则或界面问题，跟"服务没起来"无关。

 ── B. 卡在超级课程表启动页，进不去也退不出 ──

 根因1：观察窗口只有 6 秒。弱网下"启动页 → SDK 拉素材 → 广告盖上来"
   常要 8~12 秒，窗口在广告出现之前就关掉了。
   修法：splashWindowMs 默认 6000 → 12000。

 根因2：v3.3 的"首屏切走收手"把"启动页 → 广告页"判反了。早停条件是
   "界面文字与首屏指纹差异 ≥ 50% 且没命中候选就收工"，而"启动页换成
   广告页"恰好就是大幅换屏 —— 广告刚盖上来，服务主动收手了。
   修法：firstScreenExit 默认改为 false（逻辑保留，默认不生效）。

 根因3：v3.3 的"离开应用"分支少了 return（真 BUG）。它只 endWatch()
   然后继续往下跑，于是又在桌面上重开一轮 6 秒观察：桌面包名在
   excludeApps 里 → 窗口全被跳过 → 兜底用"当前活动窗口"扫桌面 →
   桌面上若有像「跳过」的字就会被点，而且每回桌面都重置一次。
   所谓"退出即停"实际上从未生效过。
   修法：endWatch() 后立刻 return。

 根因4：跳过按钮是纯图片/视频覆盖层时，控件树里根本没有节点，找候选
   必然为空，只能干等超时。
   修法：新增"卡住自救"（backKeyFallback，默认开）—— 必须同时满足
     · 确认当前确实是广告页（命中 adTexts 里的特征文案）
     · 这种情况已持续 backKeyDelayMs（默认 3500 毫秒）
     · 本轮既没跳过成功、也没按过返回
   才按一次返回键（performGlobalAction(GLOBAL_ACTION_BACK)）。
   普通界面绝不会触发。
   为什么安全：广告 SDK 普遍把开屏页的返回键重写成"结束广告"，
   对用户等价于跳过，也正是"退不出"的唯一出路。

 ── 两处不再一刀切 ──
 · 不安全候选不再一次就收工：unsafeRejectLimit 默认 3
   （v3.3 是第一次就 endWatch，容易被广告页里的正常按钮骗走）。
 · 冷却只对"上一轮真跳成了"生效：新增 lastEpisodeHit 记录上一轮是否
   真跳成功，没成功就不冷却 —— 否则"开机那一下没跳成，之后怎么开都
   不跳，要白等一分钟"。冷却时长也从 60 秒收紧到 8 秒。

 ── 顺带修掉卡顿 ──
 v3.3 的扫描(100ms) + 轮询(250ms) + 点击前复核(整窗口全树深搜) 全在
 主线程，观察期内界面发涩。v3.4 把整套状态机搬到独立后台线程
 （skipad-worker），主线程只留 Toast 和震动。

 ── 超级课程表专项 ──
 apps 里新增「超级课程表」(com.tencent.pocket) 单独规则；
 ID 里补了倒计时角标（*countdown*、*ad_time*），因为京东那种开屏的
 「跳过 | 2」是带计时的角标；广告特征词补了「互动广告」「开屏广告」
 「跳过并关闭」—— 刻意不收裸词「广告」，那词正常页面太常见。

【v3.3 修了什么（退出即停 · 首屏切走收手）】
  你反馈的问题："着急想退回界面，这个应用没有广告的话，退出以后会反复点回去。"

  典型场景：打开一个没有开屏广告的应用（或开屏已正常结束），你马上按返回 /
  切到桌面 / 进设置改东西。此时 3.2 的观察窗口还开着，会把这个"正常界面"
  当成广告界面继续扫、反复找"跳过"去点，于是出现"明明没广告，却像被反复
  点回去"的错觉 —— 本质不是点错，而是观察收得太慢、点得太勤。

  根因：两处"观察窗口结束"不够及时。
    1) 前台切换决策没把"退出"当回事。3.2 在"观察中 + 桌面"时只把状态置为
       FG_KEEP（继续观察）。回到桌面后服务仍在扫（桌面被 excludeApps 挡下、
       不会误点，但会一直空扫、不收工），再从桌面进别的应用这轮还挂在前一个
       应用上，容易让人觉得"点回去了"。
    2) 首屏一旦切走没有早停。没命中跳过就一直扫到 6 秒 / 60 秒自然结束，而
       "没有广告、已正常进入"的情况，前 1~2 秒界面就该和开屏大不一样了。

  修法：退出即停 + 首屏切走收手。
    · 新增 FG_LEAVE 决策：观察中若前台切到「桌面 / 设置 / 安装器 / 系统 UI /
      本应用自身」等 excludeApps 包名，直接 endWatch() 立刻收工（不再像 3.2
      那样 FG_KEEP）。只剩"广告 SDK 独立窗口 / 另一个正常应用窗口"仍 FG_KEEP。
      这样用户一回到桌面，本轮观察当场结束，不再空扫、不再挂着。
    · 首屏文字指纹早停：进入观察后 3 秒内抓一次"首屏文字指纹"；之后若始终没
      命中任何候选、且当前界面与首屏指纹差异 ≥ 50%，标记 leftFirstScreen 并
      endWatch() 收工（说明已正常进入 / 离开应用）。
      阈值 0.5、起始延迟 1500ms、采集窗 3000ms，避开开屏倒计时数字变化误判。

  说明：3.2 其实有 excludeApps 兜底（桌面/设置不被扫描、不会误点），所以 3.3
  修的是"收工太慢、还在空扫"的体感问题，而非"真的点错了"。但既然会让人误以为
  被反复点，就必须收得快。
【v3.2 修了什么（大「跳过」条 / 广告 SDK 关闭键 / 互动广告）】
  你又反馈了三类还是跳不掉的广告：
  1) 有「跳过」字样却跳不掉 —— 某些开屏的「跳过」是一整条
     「文字 + 倒计时」的大宽条，面积超过了旧版的面积上限，被"太大不要"切掉了。
  2) 「互动广告」关不掉 —— 它的「关闭 / ×」常常是纯图标、又落在屏幕中部，
     既过不了"必须有文字"这道闸，也落在安全带之外。
  3) 广告 SDK 的关闭按钮 / 开屏关闭键 —— 和(2)一样，纯图标、位置不固定。

  根因：3.0/3.1 为了"宁可漏跳、绝不误触"，给按钮加了三道形状约束
  （面积必须小 + 必须靠屏幕边 + 必须有文字）。这对"小且靠边的跳过按钮"
  很准，但对上面这些"确实是跳过/关闭"的控件会一刀切错杀。

  修法：身份已确认，就解开形状约束。
  只要候选"精确命中跳过文字（如『跳过广告』『关闭』）"或"命中带 skip 的
  控件 ID（如广告 SDK 的 *close*、开屏 *splash_close*）"，就视为身份已确认
  —— 文字 / ID 本身就是铁证，于是：
    · 面积上限放到容器级 0.55（只挡真正的全屏容器，防点进广告落地页）
    · 位置不限（但仍不点全屏容器）
    · 免"必须有文字"闸门（纯图标关闭键也能点）
  无身份的小按钮（靠关键词命中）依旧走旧版的严格约束。
  唯一仍死守的硬约束：面积超过 0.55 的节点一律不点（那是广告大图/视频，
  点中会跳转），无论文字多像「跳过」。

  另外扩充了默认规则：关闭类文案新增「关闭该广告 / 点击关闭」等；
  ID 新增「开屏关闭键 *:splash_close*」等，所以更多"关不掉"的控件开箱即跳。
【v3.1 修了什么（摇一摇广告）】
 你反馈的问题：页面上出现「摇一摇」或「摇动手机」字样时，就不会自动跳过。

 这是 3.0 自己造成的 —— 不是随机失灵，而是两道闸门同时把这类广告挡住了：

 1) 安全带太窄。摇一摇广告把品牌 logo 和「摇一摇」提示放在屏幕最上面，
    于是「跳过」按钮被挤到屏幕纵向 30%~55% 那一带 —— 正好在 3.0 只允许
    的「顶部 30%」之外，被判成不安全，于是不点。

 2) 必须有文字依据。这类广告的「跳过」常常是纯图片（一个圆圈加斜杠，
    没有文字），过不了「必须文字命中」这道闸门。

 修法：不拆防线，改成"看证据放宽"。
 最省事的做法是把安全带整体放宽，但那等于全屏可点，3.0 好不容易挡住的
 误触（抖音搜索图标）会原样回来。所以 3.1 改成一个有条件的放宽：

   只有当页面上确实出现了摇一摇类特征文案时，才判定"这确实是广告页"，
   进而启用一套更宽、但仍然有边界的安全带。

 放宽后仍然守住的边界（没有变成全屏可点）：
   普通页    顶部 0~30% 可点   中间 30%~75% 不点   底部 75%~100% 可点
   摇一摇页  顶部 0~60% 可点   中间 60%~75% 不点   底部 75%~100% 可点
   面积上限也从 0.12 放宽到 0.25（摇一摇的「跳过」常是一整条宽条）
 中间那条走廊一律不点（那里是正文和输入框，误触代价最高）。

 特征词是刻意收窄的，只收「摇一摇 / 摇动手机 / 晃动手机 / 翻转手机 /
 跳转第三方」这类广告专属措辞，不收「立即下载」这种正常页面也会出现的词。
 代价是某些不含这些词的摇一摇广告仍跳不掉 —— 宁可漏放宽。

 开关：「摇一摇广告放宽」默认开，应用首页能看到它的状态。
 把它关掉，行为就完全回到 3.0。

【v3.0 修了什么（重要·防误触）】
 之前的版本有个问题：打开抖音时会误触右上角的搜索，
 打开全屏搜索时也会误触。对老人来说这比"没跳过"难受得多。
 3.0 专门解决这个，思路是：宁可不跳，也绝不点错。

 找到两个原因：
 1) 跳过按钮和搜索图标位置重合。
    抖音的「跳过」在右上角，主页的搜索图标也在右上角。
    更麻烦的是广告常由广告 SDK 画在独立窗口里，旧版会被那个
    窗口"带跑"，等广告消失、主界面回来时又在正常界面上重新
    扫了一轮，就点到搜索图标了。
    现在：观察窗口固定锚在你打开的那个应用上，不被广告窗口带走。

 2) 同一个应用内部换界面被当成了"重新打开应用"。
    旧版观察结束后，应用内任何界面变化都会重新开一轮观察，
    所以你在抖音里点开全屏搜索就又扫起来了。
    现在：区分"真的换了应用"和"同一个应用内部换界面"，
    后者不再重开；并加了 60 秒冷却。

 再加上四道防误触闸门：
 · 稳健模式（默认开）：只点"小按钮、且在屏幕顶部或底部、
   且有文字依据"的候选。屏幕正中的一律不点。
 · 点击前复核位置：广告消失后如果同一位置换成了别的图标，
   复核会发现不是原来那个，直接放弃（这就是治搜索误触的关键）。
 · 开屏期缩短到 6 秒：超过这个时间就不再扫了。
 · 同应用冷却 60 秒。

 代价：会有一部分广告跳不掉（跳过按钮特别大或位置特殊的）。
 这是故意的取舍。"没跳过"只是多点一下，"点错"会让人不知所措。
 如果你更在意跳过率，可以把「稳健模式」关掉。

【v2.1 修了什么】
 QQ音乐有时候能跳、有时候不能。不是规则问题，是时序问题：
 1) 观察窗口被无关窗口掐断了；
 2) 扫描完全靠系统事件驱动，纯图片广告可能一个事件都不发。
 现在加了主动轮询（每 250 毫秒扫一次），不再依赖事件。

【v2.0 修了什么】
 1.0 只能扫"当前活动窗口"，而开屏广告经常渲染在独立窗口里，
 所以扫不到（QQ音乐就是这样）。2.0 改成扫描全部窗口。

【安装三步】
 1. 把这个 apk 传到手机（数据线 / 微信 / QQ / LocalSend 都行）
 2. 在手机上点它安装。系统提示"不允许安装未知应用"时，
    按提示允许"文件管理"或"浏览器"安装即可
 3. 桌面会出现蓝色图标「跳过广告」

【开启（关键！不开启不会工作）】
 1. 打开「跳过广告」
 2. 点页面上蓝色的「打开无障碍设置」按钮
 3. 在列表里找「已下载的服务 → 跳过广告」，点进去，打开开关
 4. 弹出"要允许跳过广告执行以下操作吗" → 点「允许」
 5. 回到应用，顶部变成绿色「● 已启用」就成功了

【★ 列表里找不到「跳过广告」？】(最常见的问题)
 先试这两个按钮，应用首页就有：

 ▸ 「找不到「跳过广告」？点这里直达开关」
    直接跳到本服务的开关页，不用在大列表里翻找。

 ▸ 「开关是灰的？点这里解除受限设置」
    安卓13+ 对侧载安装的应用默认标记"受限设置"，无障碍开关会变灰。
    点这个按钮进应用信息页 → 右上角三点菜单 → 允许受限设置。

 还有一个原因：本应用通常被折叠在无障碍页面的
 「已下载的服务」里面，要再点进去一层，一直往下翻。

【还不行？看手机品牌】
 小米/Redmi ：设置→应用设置→跳过广告→省电策略→无限制（并在最近任务里加锁）
 华为/荣耀  ：手机管家→应用启动管理→跳过广告→关掉自动管理，三项全允许
 OPPO/一加  ：设置→电池→应用耗电管理→跳过广告→允许后台运行
 vivo/iQOO  ：设置→电池→后台高耗电→允许跳过广告
 三星       ：设置→电池→后台使用限制→把跳过广告移出"休眠应用"

【给老人用的推荐设置】
 应用首页的开关里：
 · 「稳健模式」→ 保持开启（防误触主力）
 · 「点击前复核位置」→ 保持开启
 · 「盲点兜底」→ 保持关闭（这是唯一会"盲点"的功能，风险最高）
 如果某个 App 老是误触，最省事的办法是把它加进 excludeApps
 （编辑规则里），那个 App 就不跳了，但绝不会再点错。

【怎么用】开启后什么都不用做。正常打开其他 App，
          开屏广告出现时会自动被点掉，伴随一下轻微震动。

【★ 某个 App 还是跳不掉？】
 1. 保持「抓取诊断快照」开着（默认开）
 2. 重现一次那个 App 的开屏，等广告自己结束
 3. 回到本应用，点「查看诊断」
 4. 里面会列出那个界面所有文字和可点击控件（可长按复制）
 5. 找到真正的「跳过」按钮，把它的文字填进「编辑规则」的 skipTexts 里

 快照是在开屏早期（广告还在屏幕上时）自动抓的。
 看快照开头那行「时机」：写"开屏早期"的才是你要的那条。

 如果是被安全闸门拦下的（日志里会写"已拦下不安全候选"），
 可以适当放宽 safeMaxArea（如 0.20）或 safeTopBand（如 0.40）。

 如果那个广告是摇一摇类的（页面上有「摇一摇」字样）却还是跳不掉：
 1. 先确认首页的「摇一摇广告放宽」是开着的（默认开）
 2. 去「查看诊断」，看那个页面上到底有没有 adTexts 里的文案。
    如果完全没有（连提示文字都是图片），放宽不会触发，
    这时只能调大 safeTopBand，或考虑关掉「稳健模式」

 如果日志里能看到"确认是广告页却跳不掉"，但一直没按返回键：
 去首页确认「卡住自救（按返回键）」是开着的，或把 backKeyDelayMs
 调小一点（如 2500）。反过来，如果你觉得它太急着按返回，
 就把这个开关关掉 —— 行为立刻回到"只点跳过、绝不按返回"。

 开机后完全不工作的排查顺序：
 1. 「查看日志」最上面有没有"服务自检"那一行（没有 = 服务没被拉起）
 2. 有自检但仍不跳 → 检查是不是把要跳的 App 加进了 excludeApps
 3. 没有自检 → 电池优化设成"无限制"，并在厂商的自启动/后台管理里
    允许本应用（小米/华为/OPPO/vivo/三星 各自的入口见上一节）

【安全说明】
 本应用没有申请网络权限（Manifest 里连 INTERNET 都没有），
 物理上不可能联网、不可能上传任何数据。
 只在你打开某个应用后的最初几秒内读取当前界面找"跳过"按钮，
 超时立即停止，不读取输入框。
 唯一的"主动操作"是两个点击：点跳过按钮（命中文字/ID 依据才点）、
 以及在确认是广告页且久久跳不掉时按一次返回键（可关）。
